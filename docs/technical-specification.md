# Техническая спецификация

**Проект:** `react-aria-components`  
**Версия документа:** 1.0  
**Дата:** 10 ноября 2026  
**Статус продукта:** `0.0.0`, `private: true`  
**Объект описания:** клиентское одностраничное приложение в текущем состоянии репозитория.

Документ фиксирует, как устроен проект сейчас. Он не описывает нереализованные экраны, API и пользовательские сценарии.

## 1. Назначение

Приложение показывает один доступный элемент управления: кнопку на базе Adobe React Aria Components, оформленную Tailwind CSS. Нажатие кнопки вызывает браузерный диалог `alert` с текстом `Button was pressed`.

Приложение не имеет серверной части, маршрутизации, хранилища данных, авторизации и сетевых запросов.

## 2. Границы системы

В состав приложения входят:

- HTML-оболочка `index.html`;
- точка входа React `src/main.tsx`;
- корневой экран `src/App.tsx`;
- обёртка кнопки `src/components/Button.tsx`;
- глобальные стили `src/index.css`;
- статические файлы `public/favicon.svg` и `public/icons.svg`.

Вне границ спецификации:

- содержимое `node_modules`;
- поведение библиотеки `react-aria-components` за пределами используемого компонента `Button`;
- процесс публикации пакета: пакет помечен как приватный и не предназначен для публикации.

## 5. Архитектура

Приложение — клиентский SPA без слоёв данных.

```text
index.html
  └─ #root
       └─ src/main.tsx
            └─ <StrictMode>
                 └─ src/App.tsx
                      └─ src/components/Button.tsx
                           └─ Button из react-aria-components
```

Поток события:

1. Пользователь активирует кнопку указателем или клавиатурой.
2. React Aria вызывает переданный `onPress`.
3. `App` выполняет `showMessage`.
4. Браузер показывает `alert("Button was pressed")`.

Состояние React не используется. Повторные нажатия не меняют разметку: каждый вызов снова открывает тот же диалог.

`StrictMode` включён. В режиме разработки React может вызывать чистые функции рендера дважды; обработчик `onPress` от этого не дублируется, потому что срабатывает только по действию пользователя.

## 6. Экран

Единственный экран занимает всю высоту окна (`h-screen`). Фон — `neutral-900`, текст — белый. Содержимое выровнено по центру по обеим осям.

На экране одна кнопка с подписью `Press me`. Других интерактивных элементов, заголовков и навигации нет.

Документ объявлен как `lang="en"`. Видимый текст интерфейса — английский. Заголовок вкладки — `react-aria-components`. Иконка вкладки — `/favicon.svg`. Файл `public/icons.svg` в коде не подключён.

## 7. Компонент Button

Файл: `src/components/Button.tsx`.

Публичный контракт, который реально читает компонент:

| Свойство | Назначение |
| --- | --- |
| `children` | Содержимое кнопки |
| `onPress` | Обработчик активации React Aria. Передаётся в `Button` библиотеки без изменений |

Остальные свойства вызывающего кода компонент не принимает и не пробрасывает. Стили заданы внутри компонента и снаружи не переопределяются.

Внешний вид:

- горизонтальные отступы `px-6`, высота `h-10`, скругление `rounded-md`;
- фон `bg-blue-600`, при нажатии — `data-pressed:bg-blue-700`;
- тень и переход `shadow`, `transition-all`;
- видимый фокус с клавиатуры: кольцо `ring-2` цвета `blue-600` со смещением `ring-offset-2` на фоне `neutral-900`;
- контур браузера отключён (`outline-0`).

Состояния `data-pressed` и `data-focus-visible` выставляет React Aria. Отдельной логики фокуса и нажатия в обёртке нет.

Типы свойства компонента не объявлены: параметр `props` остаётся нетипизированным. Сборка TypeScript это не запрещает, потому что в `tsconfig.app.json` не включены `strict` и `noImplicitAny`.

## 8. Стили

Tailwind CSS 4 подключается одной директивой в `src/index.css`:

```css
@import 'tailwindcss';
```

Плагин `@tailwindcss/vite` зарегистрирован в `vite.config.ts` рядом с `@vitejs/plugin-react`. Отдельного `tailwind.config.*` нет: используется конфигурация Tailwind 4 по умолчанию. Утилитные классы находятся прямо в JSX.

Свои CSS-переменные, тёмная тема через `prefers-color-scheme` и адаптивные брейкпоинты не заданы. Тёмный фон зашит классами экрана.

## 9. Сборка и команды

| Команда | Действие |
| --- | --- |
| `npm run dev` | сервер разработки Vite с HMR |
| `npm run build` | `tsc -b`, затем `vite build` |
| `npm run preview` | раздача production-сборки |
| `npm run lint` | `oxlint` по конфигурации `.oxlintrc.json` |

`tsconfig.json` сам файлы не компилирует. Он ссылается на:

- `tsconfig.app.json` — каталог `src`, `noEmit: true`, цель `ES2023`, `moduleResolution: bundler`;
- `tsconfig.node.json` — только `vite.config.ts`, модули `nodenext`.

Проверка типов при сборке идёт через project references (`tsc -b`). Исходники в браузер отдаёт Vite, TypeScript файлы не эмитит.

Включённые проверки: `noUnusedLocals`, `noUnusedParameters`, `erasableSyntaxOnly`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`.

## 10. Качество кода

Oxlint подключает плагины `react`, `typescript` и `oxc`.

| Правило | Уровень |
| --- | --- |
| `react/rules-of-hooks` | error |
| `react/only-export-components` | warn, `allowConstantExport: true` |

Проверка с учётом типов (`typeAware`) не включена.

Oxfmt настроен на отсутствие точек с запятой и сортировку классов Tailwind. В `package.json` нет скрипта форматирования: `oxfmt` установлен, но в стандартный цикл команд не входит.

Тестов, CI, линтеров доступности и e2e-проверок в репозитории нет.

## 11. Замеченные расхождения

1. `oxfmtrc.json` указывает таблицу стилей `./src/app.css`. Такого файла нет. Глобальные стили лежат в `src/index.css`, поэтому сортировка классов Tailwind форматтером сейчас смотрит не на тот файл.
2. `README.md` описывает шаблон Vite и не отражает зависимости React Aria и Tailwind.
3. Обёртка `Button` не типизирована, хотя проект на TypeScript.
4. `public/icons.svg` не используется кодом и разметкой.

## 12. Нефункциональные свойства текущей сборки

- Рендер только на клиенте. SSR, SSG и пререндер не настроены.
- Секретов и переменных окружения приложение не читает.
- Внешние запросы во время работы интерфейса не выполняются. Сеть нужна только для установки зависимостей и dev-сервера.
- Доступность кнопки обеспечивает React Aria: роль кнопки, активация с клавиатуры и атрибуты состояний. Обёртка эту семантику не подменяет собственным `<button>` или обработчиком `onClick`.
- Локализация не реализована. Язык документа зафиксирован как `en`.
